# 版本升级规则

> **版本号是唯一的更新载体**：新命名**不含年月日**，文案/图片/参数/结构任何更新都只升版本号（`V主.次`）。

| 修改类型 | 版本变化 | 版本类型 | 人工确认 |
|---|---|---|---|
| 首次发布 | V1.0 | 首版 | 是 |
| 文案/图片/翻译小修 | V1.0 → V1.1 | 小改 | 是 |
| 产品参数修正 | V1.0 → V1.1 | 错误修复/小改 | 是，**需产品负责人确认** |
| 结构/设计风格大改 | V1.0 → V2.0 | 大改 | 是 |
| 区域本地化 | 区域版本加 `-R<n>`（含区域括号），如 `…-(PK)-V1.0-R1` | 区域二创 | 视区域规则确认 |
| 错误修复 | 小版本升级并记录修复原因 | 错误修复 | 是 |
| 旧版废弃 | 主表/版本状态→已废弃 | — | 是 |

## 判定步骤
1. 判断是否关联已有物料：`record-search` 主表（按产品线/系列/区域/类型/语言匹配）。找不到则追问「新物料还是旧物料更新」。
2. 找到旧版 → 读旧版附件与记录 → 对比（文件名/页数/文本/参数/卖点/视觉/Brief，P0 先做文本与参数）。
3. 据上表判定版本类型与新版本号。参数类改动**必须**产品负责人确认。
4. 生成版本确认卡 → 人工确认 → 写版本记录表。
5. **发布后版本替换收尾**（详见 SKILL 阶段六）：新版主表「当前版本」=新版本号；新版发布后自动化 15 会把 `替代的旧版本` 指向的旧版主表设 **「发布状态=已下架」→ 触发自动化 13**（旧版本记录「版本状态=已替代」+通知旧版下载者/订阅者，按是否大文件发送新版附件或云盘链接）。旧版「是否当前有效=否」由 TClaw 回读后收尾。**保证同物料同一时刻只一条「已发布」。**
6. 版本替换的识别：07 检测到池「关联旧版本」非空会自动勾「是否为版本替换」；你据此(或主动判定)走阶段七对比，把池「关联主表/关联旧版本」连好。
