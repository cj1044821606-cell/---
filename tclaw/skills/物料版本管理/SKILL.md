# 物料版本管理（统一作业手册 · 一步步照做）

> **这是你处理物料的唯一 skill。** 不要再去找/沿用任何旧 skill。
> 依赖知识：[命名与编码规则](../../knowledge/命名与编码规则.md)、[多维表格结构](../../knowledge/多维表格结构.md)、[产品型号解码](../../knowledge/产品型号解码.md)、[版本升级规则](../../knowledge/版本升级规则.md)、[字段ID映射](../../knowledge/字段ID映射.json)。
> 工作空间：`AI物料版本管理系统`，`base_token = DPCCbp65waiDtys1JfucMKm8nTe`。**每次写表前先 `lark-cli base +field-list` 确认真实字段 ID 与选项。**

## 总流程（状态机）
```
入料 → [待识别] → 抢锁[处理中] → 识别命名
   → 信息全？ ─否→ [待补充](追问) ─用户补充→ 回[待识别]
              └是→ [待确认](确认卡) ─用户点"通过并发布/仅入库"→ 入库写表 → [已入库]
                                     └"退回"→ [已退回]
   → 若「确认后自动发布」=真 → 云盘门控 → 写发布记录+主表已发布 → 区域通知/旧版下架通知
   → 若「确认后自动发布」=假 → 停在待发布，后续可人工发布
```
对应「AI待处理池.处理状态」：待识别 / 处理中 / 待补充 / 待确认 / 已入库 / 已退回 / 失败。

## 本流程必守的 7 条（违反就会出今天的 bug）
1. **不漂移/不空等**：认领一条记录就**一口气推进到下一个真正要人确认/补充的点**，别做一步就停等人催。每条群消息都讲清「在处理哪条 TODO-xxx、当前第几步、下一步做什么」。
2. **读完必回**：每次 `record-search/list/get` 或处理动作后，**必须**把结果落表 + 在群里回一条状态；群消息发送失败要**重试到成功**；**严禁读完表就沉默**。
3. **区域照实填**：`适用区域`(fldVzP1KU3) 是**多选**；用户说哪些就填哪些（"AF 和 ME"→`[AF, ME]`）；**用户已明确时绝不用 GLOBAL 兜底**；命名只显示主区域(第一个)。
4. **入库必建版本记录**：入库**必须**在版本记录表建一条并连 `关联物料`→主表，建完 `record-get` 回读确认。
5. **附件先改标准名**：上传任何附件(M/L/S)前先把本地文件改名为标准文件名；且要在**处理池阶段**就改好（08 会原样同步到主表）。
6. **同步项不手写**：`策划及审核人/设计师/源文件(L)/预览文件(S)/当前有效附件/订阅者`(主表) 由自动化 **7.5(入库时建主表)/08** 同步，`发布时间`由 10、`内部物料ID`由 11——**别手写这些**。
7. **关键动作人工确认**：发布/下架/废弃/大版本/参数修正，一律生成确认信息等人点头；本系统已把“确认入库”和“确认首次发布”合并到确认卡的「通过并发布」按钮里，仍算人工确认。缺信息先追问，不臆测。

## 阶段一 · 入料（建待处理池记录）
三种来源：
- **群文件**（最常见）：用户在群里说"上传了新文件/发了文件" → 见下「群文件下载铁律」。
- **表单**：飞书表单写入「AI待处理池」，自动化 07(`wkfNLwLwVpkKoHFi`) 会 @你。
- **IM 直发**：用户直接把文件发给你。

**群文件下载铁律**（不照做会报 400）：
1. `lark-cli im +chat-messages-list --chat-id <群> --as user` 在本群近 20 分钟里找到那条**文件消息**。
2. 从消息里同时取 `message_id(om_xxx)` 和 `file_key(file_xxx)`。
3. `lark-cli im +messages-resources-download --message-id <OM> --file-key <FILE> --type file` 下载到工作目录（**只用 file_key 会 400**）。
4. 同一文件若已建过记录，不重复建。

**建记录**：写「AI待处理池」(`tblcAERSb9EKbx5W`)：挂上附件、填 `上传方式/上传者`、（若已知）`策划人及审核人(flddEKvsOe)/设计师(fldOR3yRgq)`，置 `处理状态=待识别`。`原始文件名` 一般由自动化 06 自动填，空了你兜底写。

## 阶段二 · 识别与命名
1. **抢锁**：`record-update` 置 `处理锁(fldHrLogC3)=是`、`处理状态(fld2LqhmT5)=处理中`。（已被锁则跳过，防并发。）
2. **取导出件 M**：下载待处理池 `上传文件(fldcOKGnHe)`（PDF/PNG/JPG/MP4，AI 据此识别）。**源文件 L 读不了，只存档，别拿来识别。** 只有 L 没有 M → 走阶段三让上传者补一份导出件。
   - 先读 `命名模式(fldK1XDsAi)`。`AI 自动识别` 或空值时按原流程识别；`我提供命名信息` 时，读取 `用户提供·物料大类/产品型号/物料类型/语言/主区域/版本号/品牌或展会名/展会年份` 作为**强结构化线索**。
   - 用户提供的字段和 `用户提供·命名预览(fld28r7jaG)` 都不是最终事实。必须对照导出件 M、用户说明和当前命名规则逐项校验；冲突或缺项只集中追问一次，不能静默采信，也不能把“预览”说成“识别成功”。
   - 校验通过后重新生成命名，并用 `record-search` 查主表 `标准命名` 是否冲突；仅在真实冲突时追加 `-NN`。最终结果仍写入 `AI识别结果`，之后再改附件名和入库。
3. **先判物料大类**：产品物料 / 品牌物料 / 展会物料。再按 [命名与编码规则](../../knowledge/命名与编码规则.md) 识别各段：
   - **产品物料** → `产品型号-物料类型-语言-(区域)-版本号`，例 `IPV-1K612U-Datasheet-En-(PK)-V1.0`。
     - 产品型号：**照搬真实型号串**（如 `IPV-1K612U`，含连字符，不解码）。
     - 物料类型：取「物料类型」选项**开头的英文 token**（Folder/Flyer/Datasheet/DetailPage/KV/Manual/USP/ProductVideo/InstallVideo/Photo/IDImage/Packaging/Social/Brochure/Logo/VI/Poster/PPT/Training）。
     - 语言：PascalCase（En/Cn/Fr/Ar/Es）。
     - 区域：`(市场码)` 如 `(PK)`；Global/无区域**省略整段**；多区域只显示主区域。
   - **品牌物料** → LOGO `<品牌>-Logo-…`（带品牌，如 `itel-Logo-V1.0`）；其余（画册/折页/datasheet）`物料类型-语言-(区域)-版本号`（不带品牌）。
     - **色彩变体**（RGB/CMYK 等看着一样、需区分的）：**合并到同一条记录**，文件名在版本号前加 `-<RGB|CMYK>` 区分（如 `itel-Logo-RGB-V2.0-M.png`/`itel-Logo-CMYK-V2.0-M.png`），别另建记录。见命名规则「变体后缀」。
   - **展会物料** → `(年份)展会名缩写-物料类型-(区域)-版本号`（**无语言段**），例 `(2026)GITEX-Poster-(PK)-V1.0`。
   - 一份产品标准资料包 = 同一产品型号、多种物料类型各一条记录。
4. **信息全不全**：缺关键项（型号/区域/语言/类型不明，或只有 L 没 M）→ 阶段三追问。齐全 → 下一步。
5. **生成定义**：标准命名（先 `record-search` 主表查重，冲突尾部加 `-NN`）、各形态标准文件名(`标准命名-<L|M|S>.<扩展名>`)、物料名称(中文可读)、初始版本号(首版 V1.0；旧物料更新见 [版本升级规则](../../knowledge/版本升级规则.md))、风险标签 → 结构化写入 `AI识别结果(fldPYFZ0De)`。
6. **【关键】处理池里就把附件改成标准名重传**：`上传文件`→标准名-M、`源文件(L)`→-L、`预览文件（S）`→-S。因为入库时附件由自动化 08 从池里**原样同步**到主表，名字必须在池里就对。
7. **旧物料更新/版本替换**：`record-search` 主表按 产品型号/物料类型/语言/区域 找旧版，连上池里 `关联主表(fldDqDp3by)/关联旧版本(fldRHigFMa)` → 阶段七对比。
8. **读完必回**：把识别结论在群里回一条（"TODO-xxx 已识别为 X，下一步 Y"）。

## 阶段三 · 信息追问（缺了才走）
1. 归纳缺/冲突点 → 写池 `缺失信息(fldhhwUMRh)`。
2. **解析追问对象**（要真实 open_id）：先查**人员定义表**(`tblMXYsjBpmnVDyc`，字段 `文本`=角色、`人员`、`区域标识`)按角色/区域匹配取 `人员` open_id；查不到再 `lark-cli contact +search-user` 或问上传者/策划。写入池 `AI追问对象(fldDEmbGoY)`。

| 缺什么 | 问谁 | 怎么问 |
|---|---|---|
| 只有源文件L、缺可读导出M | 上传者/设计师 | 请补一份导出 PDF/PNG/JPG（源文件 AI 读不了）|
| 型号识别不出 | 上传者/策划 | 这物料对应哪个产品型号？|
| 参数疑似冲突 | 产品负责人 | 功率/容量以规格书为准？|
| 适用区域不明 | 上传者/区域营销 | 适用哪个/哪些市场？|
| 是否外发不明 | 策划/审核人 | 是否允许发给客户？|
| 版本关系不清 | 上传者/设计师 | 新物料还是基于旧版改？|
| 品牌物料口径 | 上传者/策划 | 按品牌物料还是指定主产品线？（**只问一次**）|

3. 置 `处理状态=待补充`、释放 `处理锁=否`。自动化 02(`wkfFY1EaZrCcnLPn`) 会把「缺失信息」推给追问对象，你不必自己发。
4. 用户补充后回阶段二重识别。**精准追问：只问缺的、问对人、一次问清。**

## 阶段四 · 确认卡（待确认）
1. 把汇总写进池记录（`AI识别结果` + 对应字段）：物料名称、标准命名、物料类型、产品型号、**适用区域**、语言、版本号、本次更新点、风险、是否外发/推荐、旧版处理建议、通知对象。（标准命名是唯一标准名；各附件文件名按 `标准命名-L|M|S.ext` 自带，不写单独字段。）
2. 置 `处理状态=待确认`。自动化 01(`wkf7HtfbF32H6kCq`) 通知上传者确认。
3. **群消息回执 + CTA**：把关键信息复述一遍，**尤其回显适用区域让用户确认**（"适用区域=AF+ME，对吗？"）。自动化 01 的确认卡有三个按钮：主按钮「通过并发布」（写 `确认结果=通过` + `确认后自动发布=true`）、次按钮「仅入库」（写 `确认结果=通过` + `确认后自动发布=false`）、「退回修改」（写 `确认结果=退回`）。

## 阶段五 · 入库写表（用户回"通过"后）
> **新模型：你把池置「已入库」→ 自动化 7.5 自动建主表记录并同步 → 你再去那条记录补身份字段 + 建版本记录。别再手建主表记录。**

前提：池里 `策划人及审核人/设计师` 已填、`上传文件(M)/源文件(L)/预览文件（S）` 已是标准名。

1. **置池「处理状态=已入库」**（`record-update` **单条更新，别用批量**，否则可能不触发 7.5）→ 自动化 7.5(`wkfCNsyMAX1hVaAA`) 自动在主表**新建一条记录**，并同步 当前有效附件/源文件(L)/预览(S)/封面图/策划及审核人/设计师/订阅者/关联处理池(→本池记录)。
2. **找到那条自动建的主表记录**：`record-search` 主表(`tbl3C5fTH08IyLkA`) 按 `关联处理池(fldHcBBjcX)` = 本池记录。**没找到=7.5 没触发**：单条重置已入库重试、或点主表「手动同步信息」按钮(09)、或排查后再继续。
3. **在这条主表记录补身份字段**（`record-update`）：物料名称(fld6wmGrLa)、标准命名(fldMZOUZZN)、产品或品牌物料、产品线(分类)、产品系列、产品型号(fldCVoZ8zt)、物料类型(fldSoGSdj8)、语言、**适用区域(fldVzP1KU3·照用户所述多选填全，别改 GLOBAL)**、当前版本=版本号、风险标签。（版本状态默认正式版/发布状态默认待发布=字段默认值；附件/人员/订阅者已由 7.5 同步，**别重复手写**。）
   - **物料ID(fldP1JPoxY·稳定族ID)**：新物料 → 把本行 `内部物料ID`(自动编号) 抄进 `物料ID`（首版编号 = 该物料的稳定ID，跨版本不变）；**版本替换** → `物料ID` = **旧版记录的 `物料ID`**（继承，使新旧同 ID），并把 `替代的旧版本(fldh1amw2f)` 连到**旧版主表记录**（下架联动靠它）。
4. **【必做】建版本记录表**(`tbl3S60VSKy1dGbj`) `record-upsert`：版本号(fldz2xwIjN)、版本类型(fld4K9D8Ml)、是否当前有效(fldhz3ZppP)=是、审核状态(fldtIxRanX)=通过、修改人(fldYHQIo7d)、本版附件(fldFQr9Rbw=标准名M)、**`关联物料(fldOpjiRlv)`=这条主表 record_id**（连上后 11 回填内部物料ID）。**版本替换**时再连 `对比旧版本`=旧版本记录。
5. **回读验证**：`record-get` 主表 + 版本记录，确认主表已自动建+身份字段补全+附件人员已同步、版本记录已建+关联物料已连。漏建版本记录 = 没有版本历史。
6. **确认后分支**：回读池 `确认后自动发布(fld2avzfPJ)`。
   - `false/空`：群回执 + CTA：「已入库，当前停在待发布；需要发布时回复 **发布**」。
   - `true`：不要停等用户第二次确认，立即进入阶段六；但必须先跑云盘门控，见阶段六第 0 步。
7. 用户回"退回" → 池 `处理状态=已退回`（自动化 03 通知上传者）；要补充则回 `待补充`。

## 阶段六 · 发布与通知（人工触发或「通过并发布」自动续跑）
0. **自动发布前门控（必做）**：如果是「通过并发布」进入本阶段，先执行 `python3 scripts/drive-upload/drive_uploader.py <主表record_id>`，随后 `record-get` 回读主表：`云盘链接M(fldYyB8ceL)`、`云盘链接L(fldpWbSOzy)`、`云盘链接S(fld0yHkFG5)`、`是否大文件(fldBwfoqhh)`。有对应附件但链接仍空时，**不要发布**；保留池 `确认后自动发布=true`，写 `处理日志` 并下轮重试/转人工。
1. **写发布记录表**(`tbl5u1ZZoCGA3UTI`)：发布标题、发布人、发布区域、发布对象、发布说明、关联物料、发布版本、旧版本处理方式。
   - 「通过并发布」默认：发布区域 = 主表「适用区域」；发布对象 = `区域营销` + `区域销售`；版本替换默认 `是否通知旧版废弃=true`、旧版本处理方式=`已替代`；发布说明用 AI 根据识别结果/版本更新点生成简短说明。
   - 人工回复“发布”时，若用户补充了发布说明/对象，以用户补充为准。
2. **主表置 `发布状态=已发布`** → 自动化 10(`wkfNXH43kGG6KiGk`) 自动给版本记录表+发布记录表盖 `发布时间`，**你不写时间**。
3. **【版本替换·旧版下架·已自动】** 新版发布后，自动化 **15(`wkfsRkBlzRytWp4P`)** 自动把 `替代的旧版本` 指向的旧版设「发布状态=已下架」（前提：入库时已连好 `替代的旧版本`）。**回读验证**旧版确已 已下架；15 没跑到就你手动设。再把旧版 `是否当前有效=否`、`当前版本` 收尾。**保证同物料只一条「已发布」。**
4. **下架通知由 13（多维表格机器人·不是你）发**：13 已启用，会给旧版**下载者(领取记录)** 与 **订阅者(fldnanZVSQ)** 发"旧版已作废 + 新版附件/云盘链接"。**你不重复发这条**（避免 AI 和机器人各发一遍），只需回读确认 13 是否触发；若运行历史失败，再人工补发。
5. **（可选）新物料首发通知**：非替换的首次发布，你可读区域配置表(`tblDbm7F8cHBUPcw`) 按适用区域取 `区域成员` 通知"新物料可用"+记录链接。

## 阶段七 · 版本更新与对比（版本替换·已转正式流程）
**何时**：池「是否为版本替换(fldxQwwS2T)」=真，或识别出是某条已有物料的新版（07 检测到关联旧版本会自动勾选）。
1. **认旧版**：`关联旧版本(fldRHigFMa)` 通常由**上传表单**(单向关联题)在入池时就填好，07 据此自动勾「是否为版本替换」。你核对+补：`record-search` 主表找旧物料，把池 `关联主表(fldDqDp3by)`=旧主表 连上（关联旧版本已指向版本表旧版）；07 没勾到就自己勾「是否为版本替换」。入库时据此继承 `物料ID`、连 `替代的旧版本`（见阶段五）。
